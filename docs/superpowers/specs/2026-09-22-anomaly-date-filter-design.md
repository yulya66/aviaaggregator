# Фильтр по датам в аномалиях + страны маршрута в карточках — дизайн

**Статус:** утверждён к реализации
**Дата:** 2026-09-22
**Скоуп:** страница `/anomalies`, лента на главной, общий модуль имён

---

## 1. Задача

Две независимые, но соседние правки.

1. **Выбор даты в аномалиях.** Сейчас `/anomalies` отдаёт все активные аномалии без фильтра по дате вылета. Нужен выбор периода «с / по», такой же, как во вкладке поиска.
2. **Страны маршрута в карточках.** Сейчас страна подписывается только у города назначения и только в ленте на главной. В аномалиях страны нет вовсе. Нужно показывать страну и вылета, и назначения, одинаково в обоих списках.

### 1.1 Не-цели

- Не трогаем фоновую задачу L3 и не гасим устаревшие аномалии в базе. Прошедшие вылеты скрываются на уровне страницы.
- Не трогаем страницу сохранённых поисков `/saved`: там список запросов, а не карточки, и назначением может быть целая страна.
- Не добавляем фильтр по хабу, скидке или цене. Только даты.

|---|---|---|
| Страница аномалий | `src/app/anomalies/page.tsx` | серверный компонент, `is_active = true`, сортировка по `discount_pct`, `limit(100)`, фильтра по датам нет |

| Поля дат | `src/components/date-range.tsx` | два нативных поля `from` / `to`, «С» дублируется в «По», `min` не даёт «По» раньше «С», календарь открывается в один клик |
| Фильтр дат в поиске | `src/app/page.tsx` | читает `searchParams`, применяет `.gte("depart_date", from)` и `.lte("depart_date", to)` |

**Найденный дефект.** Полю `is_active` у аномалий значение `false` не присваивается нигде: в `l3.ts` строки всегда пишутся с `is_active: true`, а гасит по давности только L2 и только `deals`. Значит на странице могут висеть аномалии с уже прошедшей датой вылета. Закрываем на уровне страницы (см. 3.2).

## 3. Дизайн: фильтр по датам

### 3.1 Состояние живёт в адресе

Форма отправляется методом GET на `/anomalies`, поля называются `from` и `to`, как в поиске. Адрес вида `/anomalies?from=2026-10-01&to=2026-10-31` можно сохранить и переслать. Фильтрация целиком серверная: в клиенте остаются только переключатели сортировки, которые уже есть в `AnomalyFeed`.

**Фильтр считается заданным**, если в адресе есть хотя бы один параметр — `from` или `to` — и он прошёл проверку формата. От этого зависит только текст пустого состояния (см. 3.4).

Почему не клиентский фильтр: сервер сначала обрезает выдачу до ста самых скидочных строк, и фильтр по дате внутри этой сотни терял бы аномалии, не попавшие в топ по скидке.

### 3.2 Границы запроса

Чистая функция в новом файле `src/lib/anomaly-window.ts`:

```ts
export type DateWindow = { gte: string; lte: string | null };

export function anomalyWindow(p: {
  from?: string;
  to?: string;
  today: string;
}): DateWindow;
```

Правила:

1. Даты принимаются только в формате `ГГГГ-ММ-ДД`. Всё остальное игнорируется, как будто параметр не передан.
2. Нижняя граница `gte` — максимум из `from` и `today`. Прошедшие вылеты не показываются никогда, даже когда фильтр не задан.
3. Верхняя граница `lte` ставится, только если задано `to`. Иначе `null`, и условие в запрос не добавляется.
4. `to` раньше `gte` не исправляется: запрос вернёт пустой список, страница покажет понятное объяснение и ссылку на сброс.

Вторая функция того же модуля считает пресеты:

```ts
export function presetWindow(months: number, today: string): { from: string; to: string };
```

`from` — сегодня, `to` — та же дата плюс N месяцев. Переполнение месяца (31 марта плюс 1 месяц) сдвигается на последний день целевого месяца.

Страница применяет результат к запросу до `order` и `limit`:

```ts
let q = supabase.from("anomalies").select(COLS).eq("is_active", true)
  .gte("depart_date", w.gte);
if (w.lte) q = q.lte("depart_date", w.lte);
q = q.order("discount_pct", { ascending: false }).limit(100);
```

### 3.3 Компонент фильтра

Новый клиентский компонент `src/components/anomaly-date-filter.tsx`.

- Форма `method="get"` на `/anomalies`, внутри переиспользованный `DateRange` с подписями «Вылет с» и «По» и кнопка «Показать».
- Три пресета — «Месяц», «3 месяца», «Полгода» — реализованы как обычные ссылки `/anomalies?from=…&to=…`, а не как кнопки формы. Благодаря этому `DateRange` не нужно переделывать под внешнее управление: он по-прежнему держит своё состояние сам, а при переходе получает новые `defaultFrom` / `defaultTo`.
- Четвёртая ссылка «Все даты» ведёт на `/anomalies` без параметров и сбрасывает фильтр.
- Активный пресет подсвечивается. Стиль переключателя берётся из `RouteDateControls`, чтобы вид совпадал с поиском.
- На `DateRange` ставится `key` из пары `from-to`. Без этого React сохранит прежнее внутреннее состояние полей при переходе по пресету, и поля не обновятся.

### 3.4 Пустые состояния

| Ситуация | Что видит пользователь |
|---|---|
| Фильтра нет, аномалий нет | «Аномалий пока нет — движок копит снапшоты ~14 дней» (текущий текст) |
| Фильтр задан, под него ничего не попало | «На выбранные даты аномалий нет» и ссылка «Показать все» |
| Ошибка запроса к базе | текущий текст про «обновите через минуту» |

## 4. Дизайн: страны маршрута

### 4.1 Новая функция имён

В `src/data/airports.ts`, рядом с остальными функциями имён:

```ts
export function routeCountries(origin: string, destination: string): string;
```

Правила:

| Случай | Результат |
|---|---|
| Страны разные | `Россия → ОАЭ` |
| Страна одна и та же | `Россия` |
| Известна только одна сторона | та страна, которую удалось определить, без стрелки: `Россия` |
| Обе неизвестны | пустая строка |

Пустая строка означает, что в карточке не появится ни разделителя, ни пробела: `DealCard` уже проверяет `regionNote` на пустоту.

### 4.2 Точки подстановки

| Файл | Было | Станет |
|---|---|---|
| `src/app/page.tsx`, 3 места | `regionNote: cityCountryName(destination)` | `regionNote: routeCountries(origin, destination)` |
| `src/app/anomalies/page.tsx` | поля нет | `regionNote: routeCountries(a.origin_iata, a.destination_iata)` |
| `src/components/anomaly-feed.tsx` | типа нет | в `AnomalyItem` добавляется `regionNote?: string`, прокидывается в `DealCard` |
| `src/components/deal-card.tsx` | комментарий «destination country» | комментарий про пару стран маршрута; код не меняется |

Смысл свойства `regionNote` расширяется со страны назначения до пары стран маршрута. Само свойство, его тип и разметка карточки не меняются, поэтому правка не затрагивает вёрстку.

## 5. Тесты

Vitest, как в остальном проекте. Покрываются чистые функции, компоненты и страницы тестами не покрываются — в проекте такой практики нет.

**Новый файл `src/lib/anomaly-window.test.ts`:**

1. Без параметров: `gte` равен сегодняшнему дню, `lte` равен `null`.
2. Только `from` в будущем: `gte` равен `from`.
3. `from` в прошлом: `gte` равен сегодняшнему дню.
4. Только `to`: `gte` равен сегодняшнему дню, `lte` равен `to`.
5. `to` раньше `from`: границы возвращаются как есть, без молчаливого исправления.
6. Мусор вместо даты (`2026-13-40`, `вчера`, пустая строка): параметр игнорируется.
7. `presetWindow` на 1, 3 и 6 месяцев: `from` равен сегодня, `to` сдвинут на нужное число месяцев.
8. `presetWindow` от 31 числа: результат — последний день целевого месяца, а не переход в следующий.

**Дополнения в `src/data/airports.test.ts`:** четыре случая `routeCountries` из таблицы 4.1.
